# Adaptive Floor Heating Climate

[![hacs_badge](https://img.shields.io/badge/HACS-Custom-41BDF5.svg?style=for-the-badge)](https://github.com/hacs/integration)
![version](https://img.shields.io/badge/version-v0.1.0-blue.svg?style=for-the-badge)
[![kofi](https://img.shields.io/badge/Ko--fi-Support%20Me-F16061?style=for-the-badge&logo=ko-fi)](https://ko-fi.com/plplaaa2)

Home Assistant용 학습형 바닥난방 Climate 커스텀 통합입니다. HEAT/AUTO 운전, 재실·외출 프리셋, 기본 히스테리시스 제어, 열 반응 관측과 학습 기반 예측 ON/OFF를 제공합니다. 단독 및 방별 Climate, 여러 방을 하나로 제어하는 통합 Climate를 지원합니다.

## 개발 상태

- 현재 작업 브랜치: `dev`
- 통합 도메인: `adaptive_floor_heating`
- 통합 manifest 버전: `0.1.0`
- 설치 경로: `custom_components/adaptive_floor_heating/`
- 설정 방식: 개별 제어 또는 멀티룸(통합) 선택
- 개별 제어: 히터 스위치 1개 + 해당 공간 실내 온도 센서 1개. 방별 제어는 이 설정을 방마다 추가
- 멀티룸(통합): 방 수(2~32), 공용 실내 온도 센서 1개, 방별 히터 스위치 선택
- 같은 스위치의 방 간·통합 간 중복 등록 방지(진행 중인 설정 포함)

## 설정 흐름

Home Assistant에서 통합 추가 → Adaptive Floor Heating Climate → 제어 방식을 선택합니다. 개별 제어 항목을 방마다 추가하면 각 방마다 Climate와 학습 데이터가 독립적으로 생성됩니다. 멀티룸(통합)은 방 수, 공용 실내 온도 센서, 방별 스위치를 먼저 선택합니다. 이후 두 방식 모두 `난방 설정 → 재실/외출 프리셋 온도 → 추가 온도 센서 → 설정 확인` 순서로 진행하고, 마지막 확인을 눌렀을 때 저장합니다. 취소한 설정은 저장하지 않습니다. 기존 항목의 옵션 편집도 같은 순서로 구성됩니다.

Config Flow 자체는 장치를 켜거나 끄지 않습니다. 설정을 저장하면 Climate와 진단 센서가 생성되고 기본 운전 모드는 OFF입니다. 멀티룸(통합)은 하나의 Climate와 학습 모델로 모든 방 스위치를 함께 제어합니다. 스위치가 모두 ON 또는 모두 OFF로 확인되어야 그룹 상태를 확정합니다. 혼합·불명 상태에서는 안전 잠금 후 전체 OFF를 요청합니다.

기존에 저장한 구형 `multi_zone` 항목은 자동 변환하지 않습니다. 구형 설정에는 방별 센서가 들어 있어 공용 센서를 임의로 선택할 수 없으므로, 새 멀티룸(통합) 설정을 만들고 기존 항목을 정리하세요.

## Climate 사용

기존 단독 설정을 삭제할 필요 없이 통합 파일을 갱신하고 Home Assistant를 재시작하면 Climate가 생성됩니다. 설정 → 기기 및 서비스 → 해당 통합의 엔티티에서 확인할 수 있습니다.

단독 온도조절기는 서비스형 기기로 등록되며, Climate는 해당 기기의 주 엔티티로 연결됩니다. 설정 → 기기 및 서비스 → 기기에서도 확인할 수 있습니다. 기존 Climate의 고유 식별자는 유지합니다. 연결한 히터와 온도 센서는 원래 통합 소속을 유지합니다. 기기 등록은 [공식 Device Registry 문서](https://developers.home-assistant.io/docs/device_registry_index/)의 `DeviceInfo` 방식을 따릅니다.

- Climate 운전 모드는 OFF, HEAT, AUTO입니다. HEAT는 기본 히스테리시스 제어, AUTO는 학습 기반 예측 제어를 사용합니다. OFF에서는 자동 제어를 하지 않고 외부 히터 동작을 관측·학습합니다.
- HOME/AWAY 프리셋은 각각 기본 23°C/18°C이며, 통합 옵션에서 18~30°C 범위로 조정할 수 있습니다. 프리셋을 선택하면 그 온도가 목표온도에 적용됩니다. 옵션에서 프리셋 온도를 바꾸면 해당 기본값을 사용 중인 목표온도도 재로드 후 갱신하며, Climate에서 직접 조정한 목표온도는 유지합니다.
- 시작 편차 기본값은 0.5°C입니다. HEAT는 목표온도에 도달하면 정지하고, AUTO의 기본 정지 편차는 0.5°C입니다. 목표 23°C라면 두 모드 모두 22.5°C 이하에서 시작하며, HEAT는 23°C, AUTO는 23.5°C에서 기본 정지 기준에 도달합니다. 통합 옵션에서 시작 편차와 두 모드의 정지 편차를 각각 조정할 수 있습니다.
- 최소 ON은 15분, 최소 OFF는 10분입니다. 사용자 OFF, 센서 오류와 과열 정지는 최소 ON보다 우선합니다.
- 재시작 시 센서에 기존 유효 온도가 있으면 즉시 사용합니다. 센서값이 unknown/unavailable이거나 유효한 온도가 아니면 제어를 보류하고 Climate를 unavailable로 표시합니다. 히터 OFF 확인과 최소 OFF 시간은 별도로 지킵니다.
- 통합의 구성/옵션에서 온도 편차, 최소 ON/OFF 시간, 학습 관측 온도 보고 간격 한도(기본 15분)를 변경할 수 있습니다. 저장 시 안전 정지 후 재로드합니다.
- 현재 목표온도, 요청 모드, 선택 프리셋과 오류 잠금을 저장합니다. 재시작 후 활성 모드를 복원해도 위 시작 조건을 다시 적용합니다. 이전 `자동 제어` 스위치 ON과 HEAT 조합은 AUTO로 이전합니다.

제어 평가 시 HA에 등록된 센서의 현재 상태를 읽습니다. 숫자 온도값이 유효하면 마지막 보고 시각과 관계없이 사용하며, `unknown`/`unavailable` 또는 유효하지 않은 값일 때 난방을 정지합니다. 보고 간격 한도는 열 학습 이력의 연속성만 판단하며, 오래 보고되지 않은 값을 새 학습 표본으로 만들지 않습니다. 35°C 이상 과열, 히터 통신·명령 오류 또는 외부 스위치 조작은 오류 잠금을 유지하며, 원인 해소·OFF 확인·최소 OFF 시간 이후 HEAT 또는 AUTO를 명시적으로 선택해 재개합니다. 과열 잠금은 34°C 이하에서 해제할 수 있습니다.

기기에는 진단 범주의 열 관측·학습 센서가 추가됩니다. 지연 시간은 duration, 잔열 상승은 temperature delta device class를 사용하고, 누적 사이클·제외 건수는 total-increasing 통계로 기록합니다. 각 센서에는 지표 의미에 맞는 아이콘이 설정됩니다. 변화율·가열률·신뢰도는 의미에 맞는 표준 device class가 없어 지정하지 않습니다. 온도 기울기는 최대 24시간/4,096개 보고를 보관하고 마지막 두 보고 간격이 5분 이내이면 최근 45분, 5분을 초과하면 최근 5개 유효 보고로 회귀 계산합니다. 실제 보고 시각 차이로 °C/h를 계산하며 최소 3개 보고와 10분의 시간 범위가 필요합니다. 이 방식은 변화율 센서와 AUTO 예측 ON에 적용하며, 사이클별 학습 회귀는 기존 시간 구간을 유지합니다. 난방 반응·잔열 값은 확인된 스위치 전환과 완결된 관측만 사용합니다. Phase 2 관측은 제어 결정과 히터 명령에 영향을 주지 않으며, 재시작 시 진행 중인 이력·사이클을 버립니다.

완결된 관측 사이클은 난방 반응 지연, 가열률, 잔열 상승, 최고점 지연을 각각 EWMA(alpha 0.2)로 학습합니다. 3개 기준 표본 이후에는 표준편차 3배 또는 항목별 최소 편차를 넘는 이상치를 제외합니다. 기기에서 학습 추정값, 신뢰도, 반영·제외된 사이클 수와 제외 측정 수를 확인할 수 있습니다. 집계 모델은 런타임 설정과 별도 저장소에 영구 저장합니다. AUTO에서는 유효한 냉각 기울기와 신뢰도 보정된 학습 반응 지연으로 온도가 반응 시점에 목표 이하가 될 것으로 예상되면 미리 가동합니다. 잔열 기반 정지는 학습 신뢰도를 반영하고 최소 ON 시간을 지킵니다. 잔열을 포함한 예상 최고점의 목표는 설정온도 + AUTO 정지 편차입니다(기본 설정: 23°C + 0.5°C = 23.5°C). 잔열 재가동 대기에도 같은 목표를 사용하며 실제 도달 온도를 보장하지는 않습니다. 히터가 꺼진 동안에는 잔열 추정값으로 재가동 시점을 조정합니다. 학습값 또는 유효한 기울기가 없으면 기본 히스테리시스와 타이머를 사용합니다.

완결된 난방 사이클의 ON→OFF 및 OFF→최고점 온도 응답곡선도 정규화하여 최대 24개 저장합니다. AUTO 정지 예측은 현재 가동시간과 상승 형태·기울기·곡률이 비슷한 과거 사이클의 실제 잔열 상승량을 우선 사용합니다. 비교 가능한 곡선이 3개 미만이면 기존 잔열 EWMA로 계산합니다. 평균 가열률은 진단값으로 남으며 단일 선형 온도 예측에는 사용하지 않습니다. 곡률은 충분한 보고가 있을 때 두 45분 구간의 기울기 변화로만 추정합니다. 기존 저장 모델은 집계값을 유지하고 새 곡선은 이후 완결 사이클부터 쌓입니다.

Climate 속성의 `control_state`, `faults`, `heater_confirmed_on`, `heater_command_pending`으로 대기·오류·명령 확인 상태를 확인할 수 있습니다. `hvac_action`은 확인된 스위치 상태를 나타내는 대리 지표로, 실제 버너 점화나 열공급 측정값은 아닙니다. HA의 센서 보고 시각과 낙관적 스위치 상태는 물리적 장치의 측정·동작을 보장하지 않습니다.

정상 재로드·제거에서는 OFF 확인 실패 시 감시를 유지하고 해제를 실패 처리합니다. HA 강제 종료·정전·통신 단절에서는 소프트웨어 OFF를 보장할 수 없습니다.

AUTO를 다시 선택해도 진행 중 난방은 중단하지 않습니다. HOME/AWAY를 다시 선택하면 수동으로 변경한 목표온도 대신 해당 프리셋의 설정 온도를 다시 적용합니다. 잔열에 의한 재가동 대기는 실제 난방 정지 후 관측 구간에서만 적용하며, 정지 시 온도를 기준으로 예측하고 학습된 최고점 도달 시간이 지나면 해제합니다.

ON 명령을 기다리다가 OFF로 전환한 경우, 같은 OFF 값의 재보고로 지연 ON 보호를 해제하지 않습니다. 실제 ON→OFF 전환이 확인되거나 사용자가 HEAT/AUTO를 명시적으로 선택할 때까지 보호를 유지합니다.

## 멀티룸(통합) 동작

통합 Climate 하나가 선택한 공용 실내 온도로 학습하고 방별 스위치 목록에 동일한 ON/OFF 명령을 보냅니다. 그룹 상태와 난방 관측은 모든 스위치가 같은 상태를 보고할 때만 확정합니다. 시작 시 스위치 상태가 서로 다르거나 어느 하나라도 unavailable이면 전체 OFF를 요청하고 오류 잠금을 적용합니다. 각 스위치는 이 통합 항목이 독점 소유하며 다른 항목에서 중복 선택할 수 없습니다.

실외 온도, 난방 공급 온도, 환수 온도 센서는 추가 설정 화면에서 선택할 수 있습니다. 실외 센서는 난방 종료 후 실내외 온도차로 정규화한 열손실률(1/h) 학습에 사용합니다. 공급·환수 센서를 선택하면 해당 온도가 실내 온도 이하인지 확인해 잔열 영향을 거르는 조건으로 사용합니다. 실외 센서가 없거나 필요한 센서값이 유효하지 않으면 열손실률 표본을 만들지 않습니다. 학습된 열손실률은 진단용이며 현재 HEAT/AUTO 제어에는 사용하지 않습니다.

## 로컬 설치 경로

개발 중인 통합 폴더를 Home Assistant 설정 디렉터리의 `custom_components/adaptive_floor_heating/`에 복사하거나 링크한 뒤 Home Assistant를 재시작합니다. 기존 단독 Config Flow는 사용자 환경에서 동작을 확인했습니다. Climate·난방 런타임의 실제 HA 검증은 남아 있습니다.

## Windows 개발 검증

배관 시험용 진단 센서 12개도 기본 비활성화로 제공됩니다. 공급/환수 온도, 공급−환수·공급−실내·환수−실내 온도차, 공급/환수 변화율, 완결 사이클의 정지 시 공급/환수 온도, 정지 후 실내 최고 상승량·최고점 지연, 배관 관측 상태입니다. 실제 보고를 받은 후 값이 생성되며 AUTO 제어와 기존 학습 모델에는 영향을 주지 않습니다. 유효 기간은 설정된 보고 간격 한도를 따르고, 두 입력의 보고 시각 차이가 5분을 초과하면 온도차를 계산하지 않습니다. 센서 하나만 설정해도 가능한 항목은 표시합니다.

정지 시 온도와 잔열 결과 네 항목은 같은 사이클이 완결될 때 함께 갱신하여 다음 유효 결과까지 유지합니다. 재시작 시 메모리 관측은 초기화하지만 Recorder에 기록된 이력은 별개입니다. 배관 상태 `not_configured`, `missing_input`, `heating`, `observing_residual`, `completed`, `waiting`은 각각 미설정, 입력 부족/만료, 난방 중, 잔열 관측, 완결 결과 있음, 대기를 뜻합니다. 배관 온도차는 실제 공급 열량이나 바닥 축열량을 의미하지 않습니다.

시험용 외기 보정 예측은 실측/외기 기반/혼합 냉각속도, 외기 보정 비중, 기존/외기 보정 예측 온도, 계산 상태의 개별 진단 센서 7개로 제공됩니다. 기본 비활성화이며 엔티티 설정에서 필요한 센서를 활성화하면 Recorder 설정에 따라 이력을 확인할 수 있습니다. 예측 온도는 현재부터 신뢰도 보정된 난방 반응 지연 후의 온도이며, 기존 방식과 같은 시간 범위로 비교합니다. 실제 AUTO 제어·모델 저장에는 영향을 주지 않습니다.

시험용 외기 비중은 열손실 학습 신뢰도와 두 냉각속도의 일치도를 곱해 최대 50%로 제한합니다. 이는 검증된 예측 정확도가 아닌 시험용 혼합 규칙입니다. 난방 중·잔열 관측 중·입력 또는 학습 부족 시 보정 예측은 비어 있습니다. 실내 보고 유효 기간은 마지막 간격의 두 배(최소 15분, 최대 60분)이며, 실외 보고는 설정된 보고 간격 한도를 따릅니다. 계산 상태 코드 `ready`는 계산 가능, `observing_residual`은 잔열 관측, `stale_indoor`는 실내 보고 만료, `missing_outdoor`는 유효 실외 입력 없음, `missing_heat_loss_model`/`missing_response_model`은 학습 부족을 뜻합니다. `inactive`, `invalid_indoor`, `insufficient_reports`, `heater_not_off`, `not_cooling`, `insufficient_temperature_difference`는 각각 런타임 중지, 실내 입력 오류, 표본 부족, 히터 정지 미확인, 냉각 미확인, 실내외 온도차 부족입니다.

HACS에서 아직 기본 저장소로 검색되지 않는 동안에는 **HACS → 통합 → 우측 상단 메뉴 → 사용자 지정 저장소**에서 위 저장소 주소를 추가하고 유형을 **통합(Integration)**으로 선택해 설치할 수 있습니다. 설치 후 Home Assistant를 재시작하고 통합을 추가합니다.
