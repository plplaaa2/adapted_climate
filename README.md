# Adaptive Floor Heating Climate

[![hacs_badge](https://img.shields.io/badge/HACS-Custom-41BDF5.svg?style=for-the-badge)](https://github.com/hacs/integration)
![version](https://img.shields.io/badge/version-v0.1.0-blue.svg?style=for-the-badge)
[![kofi](https://img.shields.io/badge/Ko--fi-Support%20Me-F16061?style=for-the-badge&logo=ko-fi)](https://ko-fi.com/plplaaa2)

Home Assistant용 학습형 바닥난방 Climate 커스텀 통합입니다. HEAT/AUTO 운전, 재실·외출 프리셋, 기본 히스테리시스 제어, 열 반응 관측과 학습 기반 예측 ON/OFF를 제공합니다. 단독 및 방별 Climate, 여러 방을 하나로 제어하는 통합 Climate를 지원합니다.

## 개발 상태

- 현재 작업 브랜치: `dev`
- 통합 도메인: `adaptive_floor_heating`
- 통합 manifest 버전: `0.1.0`
- 설치 경로: `custom_components/adaptive_floor_heating/`
- 설정 방식: 개별 제어 또는 멀티룸(통합) 선택
- 개별 제어: 히터 스위치 1개 + 해당 공간 실내 온도 센서 1개. 방별 제어는 이 설정을 방마다 추가
- 멀티룸(통합): 방 수(2~32), 공용 실내 온도 센서 1개, 방별 히터 스위치 선택
- 같은 스위치의 방 간·통합 간 중복 등록 방지(진행 중인 설정 포함)

## 바닥난방 사이드바 (7단계)

통합을 로드하면 Home Assistant 사이드바에 **바닥난방** 메뉴가 자동 등록됩니다. HA 내부 웹 서버에서 화면을 제공하며 별도 서버 설치나 YAML 설정은 필요하지 않습니다. 상단에는 대시보드·운전 제어·학습 분석·운전 기록 메뉴가 있고, 대시보드는 운전 중심 레이아웃으로 구성됩니다.

방/통합을 선택하면 현재·목표 온도, OFF/HEAT/AUTO, 재실/외출, 학습 모델, 히터 확인 상태, ON/OFF 명령 확인 대기, 제어 상태와 오류를 표시합니다. HA 엔티티 레지스트리에서 이 통합의 활성·표시 가능한 Climate를 식별하고, HA가 전달하는 상태 변경을 화면에 반영합니다. 이름과 엔티티 ID가 바뀌어도 고유 ID로 선택 항목을 유지합니다. 온도 단위는 HA 설정을 따르며 연결 끊김·unavailable·유효하지 않은 온도는 실제 온도로 표시하지 않습니다.

대시보드와 운전 제어 탭에는 HA Climate 상세 보기 스타일의 온도 아크와 원형 핸들이 있습니다. 아크를 누르거나 드래그한 뒤 놓으면 목표온도를 한 번 적용합니다. 조작 취소는 초안을 복구하며, 방·연결·단위 변경이나 사용 불가 상태에서는 이전 조작을 전송하지 않습니다. 목표온도는 읽기 전용 숫자로 표시하며 +/− 버튼은 누를 때마다 즉시 적용합니다. 입력창과 적용 버튼은 제공하지 않습니다. OFF/HEAT/AUTO 및 재실/외출 버튼은 선택한 Climate의 기존 HA 서비스를 호출합니다. 입력 범위·단위·증분은 해당 Climate 속성과 HA 설정을 따르며, 요청 처리 중에는 중복 요청과 방 선택을 잠급니다. 사용할 수 없는 항목은 제어할 수 없습니다. 서비스 성공은 실제 히터 전환을 의미하지 않으며, 표시값과 선택 상태는 HA 보고값을 유지합니다. 실패나 15초 응답 확인 시간 초과 시 안내하며 자동 재전송하지 않습니다. 학습·예측 설정은 카드 하단에서 펼치거나 접을 수 있습니다.

두 탭의 **AUTO 학습 모델**과 **예측 운전** 선택은 같은 설정 항목의 기존 Select 엔티티에 `select.select_option`을 호출합니다. 설정 항목 ID·통합 소유권·고유 ID로 대상을 찾으므로 엔티티 ID 변경에도 대응합니다. 기본 학습/5분 커브 및 eco/balanced/comfort 중 해당 엔티티가 지원하는 값만 선택할 수 있습니다. 누락·숨김·비활성·사용 불가 엔티티는 선택할 수 없으며 성공 이후에도 HA가 보고한 선택값을 유지합니다. 선택은 AUTO에 적용되고 기존 모델의 학습·복원·대체 동작은 그대로 따릅니다. 모델이나 예측 운전 변경으로 작성 중인 목표온도 입력을 지우지 않습니다.

대시보드와 운전 기록 탭에서 최근 6시간·24시간의 실내 온도, 목표온도와 히터 ON 확인 구간을 표시합니다. HA History·Recorder에 해당 Climate의 상태·속성이 기록되어 있어야 합니다. 활성 그래프 화면은 60초마다 조회하고 새로고침 버튼도 제공합니다. 그래프를 가리키거나 터치하면 해당 시각의 값을 확인할 수 있습니다. 마지막 기록값은 다음 보고까지 유지해 표시하며 unknown/unavailable 구간은 온도 선을 끊습니다. 히터 확인 상태는 실제 열공급 측정값이 아닙니다. 표시 시간대와 단위는 HA 설정을 따르며 과거 기록 중 온도 단위를 변경한 경우 저장된 Climate 값의 단위를 따로 복구하지 않습니다. 엔티티 ID 변경 이전의 다른 ID에 저장된 기록은 이번 조회에 포함하지 않습니다.

최근 완료 사이클에는 실제 최고온도, 난방 OFF·실제 최고점·관측 완료 시각, 기존/5분 커브 모델의 예측 최고온도와 오차를 표시합니다. 오차는 **예측 − 실제**이며, 예측이 없었던 모델은 `—`로 표시합니다. 완료 결과 자체에 저장된 예측·오차만 사용하고, 신뢰도는 최근 OFF 기록과 완료 결과의 OFF 시각이 같을 때만 표시합니다. 새 OFF 기록과 이전 완료 결과를 섞지 않습니다. 시각 정보가 없는 구형 완료 결과도 온도 비교는 표시하며, 항목이 unavailable이면 과거 완료 결과라는 안내를 붙입니다. 내부 진단 온도는 섭씨이므로 화씨 설정에서는 절대온도와 오차를 각각 변환합니다.

대시보드와 학습 분석 탭에서 Cold·Warm·Predictive Warm·Cooling 종류를 선택해 Current·Long-term 커브를 비교할 수 있습니다. 그래프는 누적 온도나 OFF 응답 예측 궤적이 아니라 **각 5분 구간의 학습된 온도 변화량**입니다. Heating 종류는 난방 ON 시점부터, Cooling은 최고점부터 경과시간을 표시합니다. 0 변화량도 보존하고 누락 버킷은 연결하지 않습니다. 승인/제외 사이클 수, 두 계층의 신뢰도, 포인터·터치 시 버킷별 증거 수와 승격 횟수를 확인할 수 있습니다. Long-term 증거 수는 승격된 Current의 증거를 이어받으며 승격 횟수가 독립 사이클 수는 아닙니다.

커브는 HA 로그인 세션의 읽기 권한을 검사하는 전용 WebSocket API로 메모리의 학습 저장 결과를 조회합니다. 조회는 모델 학습·예측·히터 제어나 SQLite 쓰기를 수행하지 않습니다. 60초 갱신과 새로고침을 지원하며, 저장소 사용 불가·학습 버킷 없음·조회 실패를 구분합니다. 화씨 설정에서는 온도차에 배율만 적용합니다.

**학습 분석 탭**은 사이클 중심 화면입니다. 상단에서 4종 커브의 누적 승인/제외와 Current·Long-term 신뢰도를 확인하고, 종류·승인/제외 필터로 최근 30건 또는 100건을 조회합니다. 관측 종료 최신순 목록에서 기록을 선택하면 ON·OFF·실제 최고점·관측 종료 시각, 시작/정지/종료 사유와 최종 품질 판정을 표시합니다. Heating과 Cooling은 같은 운전에서도 별도 기록이며 진행 중인 사이클은 종료 후 표시됩니다. 대시보드의 최근 완료 사이클 비교는 이 제외 기록 목록과 별도입니다.

새로 저장되는 기록에는 시작/OFF/최고온도, OFF 시 변화율, 난방 지속시간, 최고점 지연, 잔열 상승량과 버킷 수를 보존합니다. 품질 검사 표는 실제 측정값과 당시 허용 기준을 함께 보여주며, 승인된 기록은 Current 버킷 반영 전후·증거 수·저장 시점의 신뢰도 변화·Long-term 승격 여부를 확인할 수 있습니다. 원본 5분 버킷은 그래프와 펼침 표로 표시하고 기존 학습 커브 비교는 하단에 배치합니다. 신뢰도와 승인/제외 품질 판정은 별개입니다. 최고점 확정 조건에는 당시 첫 하락·다음 보고의 추가 하락 기준과 확인값, 관측 상한을 표시하며 과거 기록에 새 기준을 덮어쓰지 않습니다.

SQLite 커브 저장소는 schema 5로 자동 이전하며 기존 승인·제외 사유를 보존합니다. 과거 기록의 누락된 측정값·판정 기준·학습 반영 전후는 추정하지 않고 기록 없음으로 표시합니다. 원본 버킷은 7일 뒤 정리되지만 사이클 metadata와 새 분석 정보는 유지됩니다. 확인된 보존기간 만료와 구형 기록의 원본 없음은 구분합니다. `adaptive_floor_heating/curve_cycles`는 엔티티 읽기 권한을 검사하고 읽기 전용 SQLite 조회만 수행하며, 화면은 60초 갱신·새로고침·방/필터 변경 시 늦은 응답 무시를 지원합니다. 압축된 HA 이력에서 생략된 상태·속성도 이전 값을 유지해 히터 ON 확인 구간의 누락을 방지합니다.

패널은 HA에서 통합이 로드된 동안 유지되며, 마지막 설정 항목을 삭제해도 재시작 전까지 표시될 수 있습니다. Windows에서 203개 Python 테스트와 네 개 Edge 검증 프로그램으로 상태·제어·이력·완료 사이클·학습 커브를 검사했습니다. 커브 검증에는 읽기 권한·소유 통합 확인, 조회 비변경성, 4종 커브·0/누락 버킷·Long-term만 있는 경우, 계층별 신뢰도, 온도차 단위 변환, 방 변경 시 늦은 응답 무시와 모바일 배치를 포함합니다. 브라우저 검증은 HA 인터페이스 대역을 사용하며 실제 HA API·Recorder·사이드바·난방 제어 검증은 남아 있습니다.

예측과 운전 카드에는 해당 방의 진단 센서 값(온도 변화율, 학습 반응·최고점 지연, 잔열 상승량, 두 모델의 예상 최고온도, 예측 신뢰도)을 표시합니다. 센서가 비활성·숨김·사용 불가이거나 학습값이 없으면 `—`입니다. 센서 자체의 HA 보고 단위를 사용하며 현재 Climate 온도 단위로 임의 변환하지 않습니다. 하단의 진단 센서 이력은 셀렉터로 센서를 선택하고 최근 6시간/24시간을 확인할 수 있습니다. 같은 설정 항목의 활성 숫자형 센서 중 **선택 기간에 유효한 숫자 이력이 있는 센서만 목록에 표시**합니다. 문자형 상태 센서와 이력 없는 센서는 제외합니다. Recorder 기록이 필요하며, 보고값을 다음 보고까지 유지하고 unknown/unavailable·단위 변경 구간은 끊습니다. 60초 갱신·새로고침·포인터/터치 값 확인을 지원합니다.

온도와 난방 운전 그래프에는 실제 히터 ON 확인·실제 예측 모델의 유효 학습 사이클 1개 이상·유효한 최신 예측 궤적이 모두 있을 때 **지금 OFF 시 잔열 예측** 점선을 표시합니다. 모델이 계산한 시간별 상대 온도 궤적을 예측 생성 시각·실내 온도에 연결하며, 예상 최고온도와 신뢰도를 함께 표시합니다. 이는 난방을 계속 켰을 때의 예측이 아닙니다. 기본 모델과 커브 대체 모델도 실제 사용한 모델 기준으로 표시합니다. OFF·사용 불가·예측 없음·생성 후 15분 초과 시 숨기며, 최소 ON 시간이나 학습 품질 조건 때문에 시작 직후에는 표시되지 않을 수 있습니다. 실측 선은 조회 종료 시각까지만 표시하고 이후 구간에는 예측만 표시합니다.

웹 UI 모듈 URL에는 파일 내용 기반 캐시 버전이 자동으로 붙습니다. UI 파일 갱신 후 HA를 재시작하고 페이지를 새로고침하면 변경된 URL로 최신 모듈을 불러옵니다. 통합의 외부 버전과 별도로 관리되므로 UI 변경 때 수동으로 캐시 버전을 올릴 필요가 없습니다.

## 설정 흐름

Home Assistant에서 통합 추가 → Adaptive Floor Heating Climate → 제어 방식을 선택합니다. 개별 제어 항목을 방마다 추가하면 각 방마다 Climate와 학습 데이터가 독립적으로 생성됩니다. 멀티룸(통합)은 방 수, 공용 실내 온도 센서, 방별 스위치를 먼저 선택합니다. 이후 두 방식 모두 `난방 설정 → 재실/외출 프리셋 온도 → 추가 온도 센서 → 설정 확인` 순서로 진행하고, 마지막 확인을 눌렀을 때 저장합니다. 취소한 설정은 저장하지 않습니다. 기존 항목의 옵션 편집도 같은 순서로 구성됩니다.

Config Flow 자체는 장치를 켜거나 끄지 않습니다. 설정을 저장하면 Climate, 예측 운전 셀렉터와 진단 센서가 생성되고 기본 운전 모드는 OFF입니다. 멀티룸(통합)은 하나의 Climate와 학습 모델로 모든 방 스위치를 함께 제어합니다. 스위치가 모두 ON 또는 모두 OFF로 확인되어야 그룹 상태를 확정합니다. 혼합·불명 상태에서는 안전 잠금 후 전체 OFF를 요청합니다.

기존에 저장한 구형 `multi_zone` 항목은 자동 변환하지 않습니다. 구형 설정에는 방별 센서가 들어 있어 공용 센서를 임의로 선택할 수 없으므로, 새 멀티룸(통합) 설정을 만들고 기존 항목을 정리하세요.

## Climate 사용

기존 단독 설정을 삭제할 필요 없이 통합 파일을 갱신하고 Home Assistant를 재시작하면 Climate가 생성됩니다. 설정 → 기기 및 서비스 → 해당 통합의 엔티티에서 확인할 수 있습니다.

단독 온도조절기는 서비스형 기기로 등록되며, Climate는 해당 기기의 주 엔티티로 연결됩니다. 설정 → 기기 및 서비스 → 기기에서도 확인할 수 있습니다. 기존 Climate의 고유 식별자는 유지합니다. 연결한 히터와 온도 센서는 원래 통합 소속을 유지합니다. 기기 등록은 [공식 Device Registry 문서](https://developers.home-assistant.io/docs/device_registry_index/)의 `DeviceInfo` 방식을 따릅니다.

새로 생성되는 엔티티 ID는 설정 항목이 하나일 때 `climate.adaptive_heating_climate`, `sensor.adaptive_heating_climate_temperature_slope`처럼 짧게 구성됩니다. 설정 항목이 둘 이상이면 설정 순서대로 `room_1`, `room_2`를 붙여 `climate.adaptive_heating_climate_room_1`, `sensor.adaptive_heating_climate_room_2_temperature_slope` 형식을 사용합니다. 셀렉터도 같은 규칙을 따릅니다. 설정 제목에는 히터 스위치 엔티티 ID를 넣지 않습니다. 자동화에서 기존 엔티티 ID를 참조한다면 변경 후 확인하세요.

- Climate 운전 모드는 OFF, HEAT, AUTO입니다. HEAT는 기본 히스테리시스 제어, AUTO는 학습 기반 예측 제어를 사용합니다. OFF에서는 자동 제어를 하지 않고 외부 히터 동작을 관측·학습합니다.
- 별도 `예측 운전 모드` 셀렉터는 AUTO의 예측 ON 강도를 고릅니다. eco는 예측 ON을 사용하지 않고, balanced는 학습된 반응 지연의 절반만 반영하며, comfort는 전체를 반영합니다. 세 단계 모두 난방 중 잔열 기반 예측 OFF를 사용합니다. 기본값은 balanced이며 선택값은 재시작 후 복원합니다. 이미 저장된 선택값은 유지합니다. HEAT/OFF 운전에는 영향을 주지 않습니다.
- `AUTO 학습 모델` 셀렉터는 기본 학습과 5분 커브 학습 중 AUTO가 사용할 모델을 고릅니다. 기본값은 기본 학습이며 선택값은 재시작 후 복원합니다. 커브 표본이 부족하거나 저장소를 사용할 수 없으면 기본 학습으로 대체합니다. 모델 변경은 진행 중인 난방을 강제로 중단하지 않습니다.
- HOME/AWAY 프리셋은 각각 기본 23°C/18°C이며, 통합 옵션에서 18~30°C 범위로 조정할 수 있습니다. 프리셋을 선택하면 그 온도가 목표온도에 적용됩니다. 옵션에서 프리셋 온도를 바꾸면 해당 기본값을 사용 중인 목표온도도 재로드 후 갱신하며, Climate에서 직접 조정한 목표온도는 유지합니다.
- 시작 편차 기본값은 0.5°C입니다. HEAT는 목표온도에 도달하면 정지하고, AUTO의 기본 정지 편차는 0.5°C입니다. 목표 23°C라면 두 모드 모두 22.5°C 이하에서 시작하며, HEAT는 23°C, AUTO는 23.5°C에서 기본 정지 기준에 도달합니다. 통합 옵션에서 시작 편차와 두 모드의 정지 편차를 각각 조정할 수 있습니다.
- 최소 ON은 15분, 최소 OFF는 10분입니다. 사용자 OFF, 센서 오류와 과열 정지는 최소 ON보다 우선합니다.
- 재시작 시 센서에 기존 유효 온도가 있으면 즉시 사용합니다. 센서값이 unknown/unavailable이거나 유효한 온도가 아니면 제어를 보류하고 Climate를 unavailable로 표시합니다. 히터 OFF 확인과 최소 OFF 시간은 별도로 지킵니다.
- 통합의 구성/옵션에서 온도 편차, 최소 ON/OFF 시간, 학습 관측 온도 보고 간격 한도(기본 15분)를 변경할 수 있습니다. 저장 시 안전 정지 후 재로드합니다.
- 현재 목표온도, 요청 모드, 예측 운전 셀렉터 값, 선택 프리셋과 오류 잠금을 저장합니다. 재시작 후 활성 모드를 복원해도 위 시작 조건을 다시 적용합니다. 이전 `자동 제어` 스위치 ON과 HEAT 조합은 AUTO로 이전합니다.

제어 평가 시 HA에 등록된 센서의 현재 상태를 읽습니다. 숫자 온도값이 유효하면 마지막 보고 시각과 관계없이 사용하며, `unknown`/`unavailable` 또는 유효하지 않은 값일 때 난방을 정지합니다. 보고 간격 한도는 열 학습 이력의 연속성만 판단하며, 오래 보고되지 않은 값을 새 학습 표본으로 만들지 않습니다. 35°C 이상 과열, 히터 통신·명령 오류 또는 외부 스위치 조작은 오류 잠금을 유지하며, 원인 해소·OFF 확인·최소 OFF 시간 이후 HEAT 또는 AUTO를 명시적으로 선택해 재개합니다. 과열 잠금은 34°C 이하에서 해제할 수 있습니다.

기기에는 진단 범주의 열 관측·학습 센서가 추가됩니다. 지연 시간은 duration, 잔열 상승은 temperature delta device class를 사용하고, 누적 사이클·제외 건수는 total-increasing 통계로 기록합니다. 각 센서에는 지표 의미에 맞는 아이콘이 설정됩니다. 변화율·가열률·신뢰도는 의미에 맞는 표준 device class가 없어 지정하지 않습니다. 온도 기울기는 최대 24시간/4,096개 보고를 보관하고 마지막 두 보고 간격이 5분 이내이면 최근 45분, 5분을 초과하면 최근 5개 유효 보고로 회귀 계산합니다. 실제 보고 시각 차이로 °C/h를 계산하며 최소 3개 보고와 10분의 시간 범위가 필요합니다. 이 방식은 변화율 센서와 AUTO 예측 ON에 적용하며, 사이클별 학습 회귀는 기존 시간 구간을 유지합니다. 난방 반응·잔열 값은 확인된 스위치 전환과 완결된 관측만 사용합니다. Phase 2 관측은 제어 결정과 히터 명령에 영향을 주지 않으며, 재시작 시 진행 중인 이력·사이클을 버립니다.

완결된 관측 사이클은 난방 반응 지연, 가열률, 정지 후 추가 상승량, 최고점 지연을 각각 EWMA(alpha 0.2)로 학습합니다. 기본 모델과 커브 모델은 셀렉터 선택과 관계없이 각각 학습하고, AUTO 제어에는 선택한 모델을 사용합니다. 기본 모델의 예측 ON은 실측 냉각 기울기와 학습 반응 지연을 사용하며, OFF 이후에 처음 나타나는 상승도 반응 지연으로 관측합니다. 예측 OFF는 상승 중에는 등가 반응 시간과 현재 속도를 사용하고, 상승 전에는 유사한 가동시간·시작 온도·ON 중 온도 변화·시작 전 기울기·이전 OFF 경과시간의 실제 추가 상승량을 직접 사용합니다. 정상 예측 정지는 최소 ON 시간을 지키며, 비교 가능한 학습이 부족하면 기본 히스테리시스로 운전합니다. Peak 판단 상한은 설정온도 + AUTO 정지 편차입니다(기본 설정: 23°C + 0.5°C = 23.5°C). 실제 도달 온도를 보장하지는 않습니다.

커브 모델의 예측 OFF는 현재 가동시간·상승 속도와 열상태가 유사한 OFF 조건의 Current/Long-term 온도 궤적을 선택·혼합합니다. 초기 정체·소폭 하락·뒤늦은 상승도 보존합니다. 과거 ON 구간을 지금 OFF한 이후의 반응으로 연장하지 않습니다. 유효한 실측 표본이 최소 3개이고 신뢰도가 충분해야 예측을 적용하며, 부족하면 기본 모델로 대체합니다. 상승 전 예측은 열상태 기록이 필요하며 불명 조건과 상태 차이는 신뢰도를 낮춥니다. 기본 모델 schema 5는 schema 1~4를, 커브 SQLite schema 4는 schema 1~3을 보존해 이전합니다. Climate 속성 `off_prediction`은 예상 Peak와 실제 사용한 메모리 계층·Current 비중을, `last_peak_comparison`은 두 모델의 예상 Peak와 실측 오차를 표시합니다.

커브 종류별 Current는 새 유효 사이클을 20% 반영하며, 충분한 표본·낮은 분산·연속 구간 조건을 만족한 Current만 Long-term에 2%씩 반영합니다. 두 계층 모두 저장하며 Raw 7일 정리로 삭제하지 않습니다. Current의 최신성 비중은 갱신 후 30일에 걸쳐 감소하지만 Long-term은 난방 비수기에도 유지합니다. 실제 예측은 Current 신뢰도에 따라 혼합하고, Current가 부족하거나 오래되면 Long-term을 사용합니다. 이 구조는 난방 반응 지연, Cooling 예측 ON과 OFF 응답에 모두 적용됩니다. `curve_memory` 속성에서 커브별 신뢰도·승격 횟수·장기 갱신 시각을 확인할 수 있습니다.

커브 학습은 Cold, Warm, Predictive Warm, Cooling을 각각 독립된 5분 변화량 표준으로 기록합니다. AWAY가 연속 3시간 이상 지속된 뒤 HOME으로 복귀하면 첫 유효 난방을 Cold로 학습하며, 해당 사이클이 학습에 반영되기 전 중단되면 Cold 대기를 유지합니다. HOME에서 히터가 오래 꺼져 있다는 이유만으로 Cold가 되지 않습니다. AWAY 사이클은 커브 표준 학습에서 제외합니다. 변화가 없는 유효 구간도 0 버킷으로 보존하며 유효 사이클을 기존 표준 80%와 새 사이클 20%로 반영합니다. 두 모델은 난방 반응 확인 후 관측 최고온도에서 0.3°C 이상 내려간 실제 보고를 확인하고, 다음 보고가 그 값보다 0.1°C 이상 더 내려가면 Peak를 확정합니다. 예를 들어 최고온도 26.6°C에서 26.3→26.2°C이면 확정하고, 26.3°C가 반복되거나 0.1~0.2°C만 등락하면 기다립니다. 실제 최고온도의 마지막 보고 시각과 확인 시각은 분리하며 초기 하락·한 번의 하락·중복 보고·타이머만으로 끝내지 않습니다. Peak 대기는 OFF부터 최대 4시간, 냉각 관측은 Peak부터 최대 3시간을 한도로 하며 다음 ON이나 지속 상승에서도 종료합니다. OFF 응답 품질 판정·저장 복원·예측의 최고점 지연 범위도 240분으로 맞춥니다. 반응 없이 제한에 도달한 기록은 정상 Peak로 학습하지 않습니다. 원시 버킷은 7일 뒤 정리하지만 학습 표준과 최대 24개의 OFF 응답은 유지합니다. 예측 ON에는 연속 구간이 충분한 Cooling 커브와 학습한 난방 반응 지연을 사용합니다. 센서 오류·수동 개입·큰 커브 이탈·신뢰도와 제어 안전 기준은 유지하며 현장 검증이 필요합니다.

Climate 속성의 `control_state`, `faults`, `heater_confirmed_on`, `heater_command_pending`으로 대기·오류·명령 확인 상태를 확인할 수 있습니다. `hvac_action`은 확인된 스위치 상태를 나타내는 대리 지표로, 실제 버너 점화나 열공급 측정값은 아닙니다. HA의 센서 보고 시각과 낙관적 스위치 상태는 물리적 장치의 측정·동작을 보장하지 않습니다.

[난방 학습 및 AUTO ON/OFF 제어 다이어그램](docs/heating_learning_and_auto_control.md)을 별도 문서에서 확인할 수 있습니다.
[5분 커브 학습 구현 규칙](docs/curve_learning.md)에는 커브 경계, 품질 판정, 저장 및 모델 대체 경로를 정리했습니다.

[모델별 작동 로직](docs/model_operation.md)에는 기본/커브 모델의 학습, ON/OFF 예측과 계산 기준을 정리했습니다.

[실측 그래프용 센서 구성](docs/sensor_layout.md)에는 핵심·상세·시험 센서와 권장 그래프 배치를 정리했습니다. 센서 42개 중 새 설치에서는 핵심 15개를 기본 활성으로 제공합니다. OFF 당시 기본/커브 예측 최고 온도, 실제 최고점, 각 모델 오차, 해당 예측 신뢰도와 관측·예측 상태를 그래프로 확인할 수 있습니다. 최근 OFF 예측과 완결된 실제 결과는 서로 다른 회차일 수 있으므로 `off_at` 속성으로 구분합니다. 기존 엔티티 ID와 활성 설정은 유지합니다.

## 주의 사항

- HA가 난방 ON 중이거나 OFF 후 최고온도를 관측하는 중에 재시작하면 해당 진행 중 사이클과 메모리의 온도 이력은 버립니다. 재시작 전후의 기록을 이어 붙여 학습하지 않습니다. 첫 사이클이 완결되기 전에 재시작했다면 그 사이클은 학습값에 반영되지 않습니다.
- 재시작 전에 완결되어 저장된 학습 지표와 응답곡선은 복원합니다. AUTO 모드와 목표온도도 복원하지만, 현재 히터 상태를 다시 확인하고 필요한 경우 OFF로 전환한 뒤 최소 OFF 시간을 지켜 제어를 재개합니다.
- 정상 종료·재로드에서는 학습 모델을 저장합니다. 정전이나 강제 종료 직전에 완료된 사이클은 저장 대기 중이었다면 유실될 수 있습니다. HA 강제 종료·정전·통신 단절에서는 소프트웨어 OFF도 보장할 수 없습니다.

정상 재로드·제거에서는 OFF 확인 실패 시 감시를 유지하고 해제를 실패 처리합니다.

AUTO를 다시 선택해도 진행 중 난방은 중단하지 않습니다. HOME/AWAY를 다시 선택하면 수동으로 변경한 목표온도 대신 해당 프리셋의 설정 온도를 다시 적용합니다. 잔열에 의한 재가동 대기는 실제 난방 정지 후 관측 구간에서만 적용하며, 정지 시 온도를 기준으로 예측하고 학습된 최고점 도달 시간이 지나면 해제합니다.

ON 명령을 기다리다가 OFF로 전환한 경우, 같은 OFF 값의 재보고로 지연 ON 보호를 해제하지 않습니다. 실제 ON→OFF 전환이 확인되거나 사용자가 HEAT/AUTO를 명시적으로 선택할 때까지 보호를 유지합니다.

## 멀티룸(통합) 동작

통합 Climate 하나가 선택한 공용 실내 온도로 학습하고 방별 스위치 목록에 동일한 ON/OFF 명령을 보냅니다. 그룹 상태와 난방 관측은 모든 스위치가 같은 상태를 보고할 때만 확정합니다. 시작 시 스위치 상태가 서로 다르거나 어느 하나라도 unavailable이면 전체 OFF를 요청하고 오류 잠금을 적용합니다. 각 스위치는 이 통합 항목이 독점 소유하며 다른 항목에서 중복 선택할 수 없습니다.

실외 온도, 난방 공급 온도, 환수 온도 센서는 추가 설정 화면에서 선택할 수 있습니다. 실외 센서는 난방 종료 후 실내외 온도차로 정규화한 열손실률(1/h) 학습에 사용합니다. 공급·환수 센서를 선택하면 해당 온도가 실내 온도 이하인지 확인해 잔열 영향을 거르는 조건으로 사용합니다. 실외 센서가 없거나 필요한 센서값이 유효하지 않으면 열손실률 표본을 만들지 않습니다. 학습된 열손실률은 진단용이며 현재 HEAT/AUTO 제어에는 사용하지 않습니다.

## 로컬 설치 경로

개발 중인 통합 폴더를 Home Assistant 설정 디렉터리의 `custom_components/adaptive_floor_heating/`에 복사하거나 링크한 뒤 Home Assistant를 재시작합니다. 기존 단독 Config Flow는 사용자 환경에서 동작을 확인했습니다. Climate·난방 런타임의 실제 HA 검증은 남아 있습니다.

## Windows 개발 검증

배관 시험용 진단 센서 12개도 기본 비활성화로 제공됩니다. 공급/환수 온도, 공급−환수·공급−실내·환수−실내 온도차, 공급/환수 변화율, 완결 사이클의 정지 시 공급/환수 온도, 정지 후 실내 최고 상승량·최고점 지연, 배관 관측 상태입니다. 실제 보고를 받은 후 값이 생성되며 AUTO 제어와 기본 학습 모델에는 영향을 주지 않습니다. 유효 기간은 설정된 보고 간격 한도를 따르고, 두 입력의 보고 시각 차이가 5분을 초과하면 온도차를 계산하지 않습니다. 센서 하나만 설정해도 가능한 항목은 표시합니다.

정지 시 온도와 잔열 결과 네 항목은 같은 사이클이 완결될 때 함께 갱신하여 다음 유효 결과까지 유지합니다. 재시작 시 메모리 관측은 초기화하지만 Recorder에 기록된 이력은 별개입니다. 배관 상태 `not_configured`, `missing_input`, `heating`, `observing_residual`, `completed`, `waiting`은 각각 미설정, 입력 부족/만료, 난방 중, 잔열 관측, 완결 결과 있음, 대기를 뜻합니다. 배관 온도차는 실제 공급 열량이나 바닥 축열량을 의미하지 않습니다.

시험용 외기 보정 예측은 실측/외기 기반/혼합 냉각속도, 외기 보정 비중, 기존/외기 보정 예측 온도, 계산 상태의 개별 진단 센서 7개로 제공됩니다. 기본 비활성화이며 엔티티 설정에서 필요한 센서를 활성화하면 Recorder 설정에 따라 이력을 확인할 수 있습니다. 예측 온도는 현재부터 신뢰도 보정된 난방 반응 지연 후의 온도이며, 기존 방식과 같은 시간 범위로 비교합니다. 실제 AUTO 제어·모델 저장에는 영향을 주지 않습니다.

시험용 외기 비중은 열손실 학습 신뢰도와 두 냉각속도의 일치도를 곱해 최대 50%로 제한합니다. 이는 검증된 예측 정확도가 아닌 시험용 혼합 규칙입니다. 난방 중·잔열 관측 중·입력 또는 학습 부족 시 보정 예측은 비어 있습니다. 실내 보고 유효 기간은 마지막 간격의 두 배(최소 15분, 최대 60분)이며, 실외 보고는 설정된 보고 간격 한도를 따릅니다. 계산 상태 코드 `ready`는 계산 가능, `observing_residual`은 잔열 관측, `stale_indoor`는 실내 보고 만료, `missing_outdoor`는 유효 실외 입력 없음, `missing_heat_loss_model`/`missing_response_model`은 학습 부족을 뜻합니다. `inactive`, `invalid_indoor`, `insufficient_reports`, `heater_not_off`, `not_cooling`, `insufficient_temperature_difference`는 각각 런타임 중지, 실내 입력 오류, 표본 부족, 히터 정지 미확인, 냉각 미확인, 실내외 온도차 부족입니다.
