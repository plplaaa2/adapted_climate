# 문제 해결

[가이드 목차](README.md) · [English](troubleshooting.en.md)

## 설정 또는 첫 실행

| 증상 | 확인 순서 |
| --- | --- |
| 센서를 선택할 수 없음 | 엔티티가 존재하는지, 숫자 상태인지, `device_class: temperature`와 `°C`/`°F` 단위인지 확인합니다. |
| Climate형 온도조절기를 선택할 수 없음 | 난방 모드·단일 목표온도·실제 `hvac_action`을 지원하는지 확인합니다. 하한·상한도 기기 지원 범위 안이어야 합니다. |
| 기기 중복 오류 | 같은 난방 기기가 다른 방이나 통합 설정에 이미 사용되는지 확인합니다. |
| 바닥난방 패널에 새 설정이 보이지 않음 | 통합 설정 완료와 엔티티 생성을 확인한 뒤 화면을 새로고침합니다. 계속되면 HA 로그의 통합 설정 오류를 확인합니다. |

## 난방이 예상대로 시작·정지하지 않을 때

| 증상 | 확인할 내용 |
| --- | --- |
| 목표온도보다 낮은데 시작하지 않음 | OFF 모드인지, 시작 편차까지 내려갔는지, 최소 OFF 대기 중인지, 오류나 잔열 대기 상태인지 확인합니다. 실제 OFF 대기는 기본값과 직전 연속 가동시간의 2배 중 큰 값입니다. |
| 목표온도에 도달했는데 즉시 정지하지 않음 | HEAT/AUTO별 정지 편차, 최소 ON 시간과 실제 기기 확인 상태를 봅니다. AUTO 예측 근거가 부족하면 기본 정지 기준을 사용합니다. |
| Climate형 OFF 요청 후에도 난방함 | 기존 온도조절기의 자체 온도가 요청 하한보다 낮은지 확인합니다. 목표온도 하한을 보냈다는 사실과 실제 난방 정지는 다릅니다. |
| 통합 멀티룸이 정지하거나 오류가 남 | 모든 스위치의 상태가 같은지, 일부가 `unknown`·`unavailable`인지 확인합니다. |
| 예상 정지 시각이 달라짐 | 예측 분석에서 현재 모델과 판단 근거를 확인합니다. 운전 중 하이브리드 판단에 따라 예약이 달라질 수 있습니다. |

오류 잠금은 원인을 먼저 해소하고 정상 센서 값과 실제 히터 OFF, 최소 OFF 대기를 확인한 뒤 HEAT 또는 AUTO를 다시 선택해 해제합니다. 같은 기기를 직접 조작하는 자동화나 스케줄도 함께 점검하세요.

## 학습·예측 관련

| 증상 | 확인할 내용 |
| --- | --- |
| 여러 번 켰는데 초기 학습이 끝나지 않음 | 학습 분석의 유효 회차 수를 확인합니다. 최고점 미확정, 수동 변경, AWAY, 일출 영향, 데이터 오류 등으로 제외되면 최소 3회에 포함되지 않습니다. |
| 최고점 확인 대기가 길어짐 | 실제 온도 하락 보고가 필요한 단계입니다. 같은 낮은 값의 반복이나 시간 경과만으로 확정하지 않습니다. 평균 오차와 일출 정보에 따라 시간 한도 적용 여부도 달라집니다. |
| 유효 3회 이후에도 기본 제어 사용 | 현재 외기·가동시간 조건에 적용할 학습 근거가 있는지 확인합니다. 3회는 모든 예측을 보장하는 횟수가 아닙니다. |
| 과거 시간 초과 기록이 복구되지 않음 | 원래 실내 센서의 Recorder 이력이 남아 있는지 확인합니다. 파생 Climate 이력이나 5분 버킷만으로는 실제 센서 보고를 대신하지 않습니다. 수동·일출 제외 회차도 복구 대상이 아닙니다. |
| 예전 회차의 원시 그래프가 없음 | 7일 원시 버킷·30일 상세 회차 보존 기간을 확인합니다. 학습 요약은 별도로 유지됩니다. |

## 진단 자료 수집

1. 사이드바 **바닥난방**에서 문제가 발생한 방을 선택합니다.
2. **학습 분석 → 학습 데이터 JSON 다운로드**로 회차와 학습 근거를 저장합니다.
3. **예측 분석 → 예측 진단 JSON 다운로드**로 현재 상태와 최근 24시간의 관련 Recorder 이력을 저장합니다. 기록 제외·보존 기간·조회 권한에 따라 내용이 제한될 수 있습니다.
4. 발생 시각과 시간대, 목표·현재온도, HEAT/AUTO 및 HOME/AWAY, 기대 동작과 실제 동작을 함께 기록합니다.
5. HA 로그에서 `custom_components.adaptive_floor_heating` 관련 오류와 경고를 확인합니다. 문제가 생긴 직후 자료를 모으면 상세 이력 만료를 피할 수 있습니다.

백업·마이그레이션 방법은 [유지 관리](maintenance.md)를 참고하세요.
