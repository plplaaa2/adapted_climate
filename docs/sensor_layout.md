# 실측 그래프를 위한 센서 구성

30분 가동 중에는 실내 온도가 거의 변하지 않아도 정지 후 뒤늦게 상승할 수 있습니다. 가동 중 변화율만으로 학습 결과를 판단하기 어려우므로, OFF 당시 두 모델의 예측과 이후 확정한 실제 최고점·오차를 함께 기록합니다.

통합 항목마다 센서 42개를 제공합니다. 새 설치에서는 핵심 15개가 기본 활성이고 상세 진단 8개, 외기 시험 7개, 배관 시험 12개는 기본 비활성입니다. 기존 엔티티의 key·unique ID는 유지하며 기존 레지스트리의 활성/비활성 설정을 강제로 변경하지 않습니다. 기존 설치에서는 기기 엔티티 목록에서 상세 항목을 직접 비활성화할 수 있습니다. 기존 사용자 지정 이름은 유지될 수 있습니다.

## 그래프에 추가할 핵심 센서

아래 key는 단독 항목의 `sensor.adaptive_heating_climate_<key>` 접미사입니다. 여러 항목을 설치하면 접두사에 `room_n`이 붙습니다.

| key | 표시 내용 | 기록 시점 |
| --- | --- | --- |
| `off_predicted_peak_existing` | 기본 모델 OFF 예측 최고 온도, °C | 제어 요청에 따른 실제 ON→OFF 확인 시 |
| `off_predicted_peak_curve` | 커브 모델 OFF 예측 최고 온도, °C | 같은 OFF 경계에서 비교 예측 |
| `actual_peak_temperature` | 관측 확정 최고 온도, °C | 실측 하락이 지속되어 최고점을 확정한 시점 |
| `off_prediction_error_existing` | 기본 모델 예측 − 실제, °C | 최고점 확정 시 |
| `off_prediction_error_curve` | 커브 모델 예측 − 실제, °C | 최고점 확정 시 |
| `off_prediction_confidence` | 해당 OFF 예측 신뢰도, % | 현재 AUTO 예측이 있으면 그 값, 없으면 최근 OFF 예측 |
| `observation_phase` | 가동 반응 대기·반응 관측·정지 후 반응 대기·최고점 확정 대기·냉각 등 | 실제 관측 진행에 따라 |
| `off_prediction_status` | 예측 사용 가능·기본 대체·최소 가동 시간 대기·관측 부족 등 | 런타임의 현재 상태에 따라 |
| `temperature_slope` | 최근 실내 온도 변화율, °C/h | 실측 보고마다 |
| `heating_response_delay` | 최근 완결 회차의 난방 반응 지연, min | 최고점 확정 시 |
| `residual_rise` | 최근 완결 회차의 OFF 온도 대비 추가 상승량, °C | 최고점 확정 시 |
| `peak_delay` | 최근 완결 회차의 OFF→최고점 지연, min | 최고점 확정 시 |
| `learned_heating_response_delay` | 기본 모델이 누적 학습한 반응 지연, min | 학습 반영 후 |
| `learned_residual_rise` | 기본 모델이 누적 학습한 잔열 상승, °C | 학습 반영 후 |
| `learned_peak_delay` | 기본 모델이 누적 학습한 최고점 지연, min | 학습 반영 후 |

예측이 없으면 온도·오차·신뢰도는 `unknown`입니다. 실제 온도나 오차를 0으로 대신하지 않습니다. 한 모델의 예측만 유효하면 해당 모델만 기록합니다. 실제 최고점은 두 모델의 예측이 모두 없어도 관측이 완결되면 기록합니다. 양의 오차는 실제보다 높게, 음의 오차는 실제보다 낮게 예측했다는 뜻입니다.

예측 최고 온도는 최근 제어된 OFF 회차의 값이고 실제 최고 온도·오차는 최근 **완결된** 관측 회차의 값입니다. 다음 난방이 시작되면 서로 다른 회차일 수 있으므로 `off_at` 속성을 확인합니다. 오차 센서는 같은 회차의 `predicted_peak`·`actual_peak`도 속성으로 제공합니다. 최고점의 실제 시각은 `peak_at`, 확정 시각은 `completed_at`에 UTC ISO 형식으로 남깁니다. Recorder 상태는 확정 시점에 갱신하며 과거 최고점 시각으로 소급 기록하지 않습니다.

OFF 예측값은 다음 제어된 OFF까지 보관합니다. 학습 근거가 부족한 다음 OFF는 예측값을 `unknown`으로 갱신합니다. 정상 저장·재시작 후에는 최근 OFF 예측과 완결 비교 결과를 복원하지만 진행 중 관측이나 재가동 대기는 이어 붙이지 않습니다. 수동 개입·센서 오류로 비교용 예측이 취소되면 보관된 과거 예측을 새 실제 최고점의 오차 계산에 사용하지 않습니다.

## 신뢰도와 상태 읽기

`off_prediction_confidence`의 `source`는 `live` 또는 `last_confirmed_off`이며 `model`은 그 신뢰도를 계산한 모델입니다. 선택한 커브 예측이 없고 기본 모델의 비교 예측이 있으면 기본 신뢰도를 제공합니다. `selected_model`로 셀렉터 선택과 구분합니다. 모델별 OFF 최고 온도 센서의 `confidence` 속성은 해당 모델의 0~1 신뢰도입니다. 보관된 예측의 신뢰도는 현재 운전에서 그 예측을 사용한다는 뜻이 아닙니다.

`learning_confidence`는 **기본 모델 평균 학습 신뢰도**입니다. 여러 열 특성 지표의 평균이며 이번 회차의 예측 신뢰도나 커브 모델 신뢰도와 다릅니다. 표시 이름을 명확히 하고 상세 진단으로 분류했습니다.

`off_prediction_status`의 `insufficient_evidence`는 조건 일치·표본·신뢰도 등을 통과한 예측이 없다는 뜻입니다. 어느 세부 조건이 탈락했는지를 임의로 단정하지 않습니다. 커브 대체 사유는 `curve_fallback_reason`, 실제 제어 결정은 `control_state` 속성으로 확인합니다. `waiting_peak`는 예측을 보관하면서 실제 최고점을 관측하는 단계입니다. 예측 최고점 시간이 지났거나 예상보다 크게 냉각되어 실제 재가동 대기가 해제되어도 최고점 관측은 계속될 수 있습니다.

## 상세 및 시험 항목

| 구분 | 기본 비활성 key | 용도 |
| --- | --- | --- |
| 상세 진단 8개 | `temperature_last_reported`, `observed_cycles`, `learned_heating_rate`, `learning_confidence`, `learned_heat_loss_rate`, `accepted_learning_cycles`, `rejected_learning_cycles`, `rejected_metric_samples` | 보고 시각·ON 가열률·평균 신뢰도·학습 수용/제외·열손실 점검 |
| 외기 시험 7개 | `experimental_*` | 외기 보정 비교; 현재 제어에 미사용 |
| 배관 시험 12개 | `water_*` | 공급·환수와 실내 온도의 독립 관측; 현재 제어에 미사용 |

`water_residual_rise`·`water_peak_delay`는 공급수·환수의 잔열이나 최고점이 아니라 **배관 시험 회차에서 관측한 실내 온도**의 잔열 상승·최고점 지연입니다. 표시 이름에 이 의미를 명시했습니다. 기본 관측과 배관 시험은 유효한 입력 조건이 다르므로 기존 엔티티는 삭제하지 않습니다.

## 권장 그래프 배치

1. 온도 그래프: 원본 실내 온도, 목표온도, 기본/커브 OFF 예측 최고 온도, 관측 확정 최고 온도. 히터 스위치 이력을 함께 표시합니다.
2. 반응 그래프: 실내 온도 변화율과 난방 관측 단계. 짧은 가동 후 지연 상승·최고점 확정 과정을 확인합니다.
3. 비교 그래프: 기본/커브 예측 오차와 OFF 예측 신뢰도. 신뢰도는 단위가 다르므로 별도 축 또는 별도 패널을 사용합니다.

기존 통합 파일을 갱신하고 Home Assistant를 재시작하면 새 센서가 등록됩니다. 센서 속성 읽기는 저장값과 메모리만 조회하며 예측 함수·히터 명령·학습 갱신을 실행하지 않습니다. 수치 센서는 measurement로 그래프를 지원하고 상태 센서는 enum을 사용합니다. 실제 HA 등록·화면 표시 및 난방 환경에서의 정확도 검증은 별도로 필요합니다.
