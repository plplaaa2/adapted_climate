# 난방 학습 및 AUTO ON/OFF 제어 흐름

현재 구현의 완결 사이클 학습과 AUTO 판단 순서를 나타냅니다. 센서·히터 상태는 Home Assistant에 보고된 값을 기준으로 합니다.
아래 도식은 기본으로 선택되는 기존 학습 모델을 설명합니다. 별도 `AUTO 학습 모델` 셀렉터로 선택하는 5분 커브 학습의 경계와 저장 규칙은 [커브 학습 문서](curve_learning.md)에 정리했습니다.

## 난방 학습 흐름

OFF·HEAT·AUTO 모두 확인된 히터 전환과 실제 실내온도 보고를 관측합니다. 아래 사이클은 히터를 끈 시점이 아니라 OFF 후 최고온도를 지나 하강이 확인될 때 완결됩니다.

```mermaid
flowchart TD
    A["확인된 히터 전환과 실내온도 보고"] --> B{"유효한 입력과 연속된 보고?"}
    B -- "아니오" --> X["진행 중 사이클 폐기"]
    B -- "예" --> C["OFF→ON: 시작 시각·온도 기록"]
    C --> D["ON 중: 온도 상승곡선과 열상태 기록"]
    D --> E["ON→OFF: 가동시간·정지 온도·기울기<br/>가능하면 곡률 기록"]
    E --> F["OFF 후: 지연 반응·잔열·최고온도 추적"]
    F --> G{"반응 확인 후 최고온도 대비 0.3°C 하락<br/>다음 실측 보고가 추가 0.1°C 하락?"}
    G -- "아니오" --> F
    G -- "예" --> H["실제 최고 온도의 마지막 보고를 Peak로 기록<br/>완결 사이클 생성"]
    H --> I["지표별 유효 범위·이상치 검사"]
    I --> J["유효 지표 EWMA 갱신·신뢰도 계산"]
    I --> K{"OFF 시 속도·가동시간과 이후 응답 유효?"}
    K -- "예" --> L["열상태·OFF 반응 표본 보관<br/>상승 전 표본 포함; 최대 24개"]
    K -- "아니오" --> M["곡선 학습 건너뜀"]
    J --> N["학습 모델 저장"]
    L --> N
    M --> N
```

센서 오류·보고 공백·재시작 또는 제어 중 예상하지 못한 스위치 전환으로 끊긴 사이클은 완결 표본으로 학습하지 않습니다. 난방 반응 지연·가열률·잔열 상승·최고점 지연은 각각 검증하며, 평균 가열률은 진단값으로 유지합니다. 현재 모델은 에어컨 운전 상태를 입력받지 않아 보일러 단독 운전과 에어컨 병행 운전의 곡선을 분리하지 않습니다.

## AUTO ON/OFF 적용 흐름

기본 제어기가 현재 온도, 오류, 시작 시 OFF 확인, 히스테리시스와 최소 ON/OFF 시간을 먼저 평가합니다. AUTO는 허용된 기본 결정에 학습값을 적용합니다.

```mermaid
flowchart TD
    A["온도 보고·히터 전환·타이머"] --> B["안전 검사와 기본 히스테리시스 결정"]
    B --> C{"운전 모드"}
    C -- "OFF" --> Z["자동 ON 명령 없음; 외부 사이클 관측"]
    C -- "HEAT" --> R["기본 결정 사용"]
    C -- "AUTO" --> D{"안전 정지·시작 대기?"}
    D -- "예" --> R
    D -- "아니오" --> E{"확인된 히터 상태"}
    E -- "OFF" --> W{"OFF 시 조건에 맞는 예상 Peak가<br/>상한 이상이며 도달시간 이전?"}
    W -- "예" --> WAIT
    W -- "아니오" --> S{"예측 운전 모드가 eco?"}
    S -- "예" --> G
    S -- "아니오" --> F{"최소 OFF 완료 + 유효한 냉각 기울기·반응 지연으로<br/>반응 시점 온도 ≤ 목표?"}
    F -- "예" --> PON["예측 ON"]
    F -- "아니오" --> G{"기본 ON 요구 + 잔열 관측 중?"}
    G -- "예" --> H{"새 OFF 표본이 없는 구형 모델에서<br/>잔열 신뢰도 충분하고 예상 Peak ≥ 상한?<br/>최고점 예상 시각 이전?"}
    H -- "예" --> WAIT["잔열 재가동 대기"]
    H -- "아니오" --> R
    G -- "아니오" --> R
    E -- "ON" --> I{"기본 결정이 계속 가열하고<br/>최소 ON 시간 완료?"}
    I -- "아니오" --> R
    I -- "예" --> J{"유사 OFF 상태 ≥ 3개,<br/>응답 분산 기준 신뢰도 충분?"}
    J -- "예" --> K["상승 중: 속도 × 등가 반응 시간<br/>상승 전: 유사 열상태의 실측 추가 상승량"]
    J -- "아니오" --> R
    K --> M{"현재 온도 + 예측 추가 상승량 ≥<br/>목표 + AUTO 정지 편차?"}
    M -- "예" --> POFF["예측 OFF"]
    M -- "아니오" --> R
    PON --> Q["히터 명령·상태 확인·다음 평가 예약"]
    WAIT --> Q
    POFF --> Q
    R --> Q
```

별도 정책 셀렉터의 기본값은 balanced입니다. eco는 예측 ON만 건너뛰고, 기본 모델에서 balanced는 학습 반응 지연에 신뢰도와 0.5를, comfort는 신뢰도만 곱합니다. 예측 OFF는 상승 중에는 등가 OFF 반응 시간을, 상승 전에는 유사 열상태의 실제 추가 상승량을 사용합니다. 신뢰도는 예측 사용 여부를 결정하며 예상 상승량 자체를 줄이지 않습니다. 정지 후 재가동 대기는 실제 OFF 기준 예상 Peak와 도달시간을 예측 ON보다 먼저 사용합니다. OFF 온도보다 0.5°C 넘게 내려가면 다시 평가하며, 구형 집계값 대기는 새 OFF 표본이 없는 모델에 한정합니다. AUTO의 기본 정지 경계는 목표온도 + 0.5°C이며 옵션에서 조정할 수 있습니다. 커브 모델의 OFF 궤적 결합과 Cooling 기반 ON은 [모델별 작동 로직](model_operation.md)을 참조하세요.
