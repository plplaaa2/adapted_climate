# 유지 관리

[가이드 목차](README.md) · [English](maintenance.en.md)

## 평소 확인할 항목

- 실내·실외 센서가 정상 온도를 보고하고, 난방 기기의 실제 상태가 통합에 보고되는지 확인합니다.
- 예측 분석에서 실제 결과와 예상 최고온도를 비교합니다. 한 회차의 오차만으로 여러 설정을 동시에 바꾸기보다, 변경 전후 조건과 여러 회차의 결과를 함께 확인하세요.
- 학습 분석에서 제외 사유를 확인합니다. 중단·외출·일출 영향 등으로 제외되는 회차가 있으므로 전체 운전 횟수와 학습 통과 횟수는 다를 수 있습니다.

## 설정 변경

통합의 옵션에서 온도 편차, 운전·보호 시간, 재실·외출 온도, 실외 온도 센서와 일출 학습용 날씨 엔티티를 조정할 수 있습니다. Climate형은 기존 온도조절기에 보낼 하한·상한도 수정할 수 있습니다. 마지막 **설정 확인** 화면에서 요약을 검토한 뒤 저장합니다. 옵션 저장은 난방 정지와 통합 재로딩을 수반하므로 진행 중인 학습이 끝난 뒤 변경하세요.

일상적인 목표온도·모드·프리셋은 Climate 또는 바닥난방 패널에서 변경합니다. 예측 ON, 최고점 관측 한도, 일출 절약 시간은 예측 운전 설정에서 관리합니다.

**난방 중에는 통합을 다시 로드하거나 재설치하지 마세요.** 히터가 이미 OFF로 확인된 뒤 다시 로드하거나 재설치하면 이전 최소 OFF 대기가 초기화됩니다. 다시 로드하거나 제거하는 과정에서 가동 중인 히터가 정지했다면, 그 정지 시점부터 재가동 대기를 적용합니다. Climate형은 연결된 온도조절기가 하한을 보고했거나 HVAC 모드가 `off`인 경우 통합에서 OFF로 확인합니다.

## 업데이트 순서

1. 난방 가동뿐 아니라 정지 후 잔열 최고점·냉각 관측도 끝났는지 학습 상태를 확인합니다.
2. 필요하면 [진단 JSON](troubleshooting.md#진단-자료-수집)을 내려받고 Home Assistant 백업을 만듭니다.
3. 모드를 OFF로 바꾸고 실제 난방 기기가 정지했는지 확인합니다. Climate형은 요청 하한만 보지 말고 실제 난방 상태를 확인하세요.
4. HACS 업데이트 또는 수동 파일 교체 후 Home Assistant를 재시작합니다.
5. 실내 센서, 실제 OFF 상태, 오류 표시와 학습 기록을 확인한 뒤 원하는 HEAT/AUTO 모드를 선택합니다.

완료된 학습은 저장소에서 복원하지만, 업데이트·재로딩으로 중단된 관측을 이어서 진행하지는 않습니다. 업데이트할 때마다 학습 리셋을 할 필요는 없습니다.

## 백업과 기록 보존

통합의 운전 상태·기초 학습은 Home Assistant의 `.storage`에, 곡선·회차 데이터는 `.storage/adaptive_floor_heating_<entry_id>_curves.sqlite3`에 저장됩니다. 복원용 백업 범위에 구성과 `.storage`, 필요한 Recorder 데이터베이스가 포함되는지 확인하세요. 실행 중인 SQLite 파일 하나만 복사하기보다 Home Assistant 백업이나 정지 후 일관된 백업을 사용하세요.

확인된 히터 상태와 확정된 종료·냉각 예측은 같은 SQLite DB에 최대 30일간 저장합니다. 업데이트 시 기존 학습과 곡선은 유지되며, 마지막으로 저장한 예측과 Recorder에서 확인할 수 있는 과거 히터 상태를 가져옵니다. 이미 누락된 예측은 빈 기록으로 남습니다. 실내온도와 목표온도 이력에는 Home Assistant Recorder를 사용합니다.

JSON 다운로드는 분석과 문제 확인을 위한 자료입니다. 현재 화면에서 이를 다시 가져와 학습을 복원하는 기능은 없습니다. 백업을 대신하는 파일로 취급하지 마세요.

| 데이터 | 보존 방식 |
| --- | --- |
| 회차별 5분 원시 버킷 | 7일 보존 후 정리 |
| 상세 회차 기록 | 30일 보존 후 정리 |
| 학습 요약·누적 예측 비교·유효 가동시간 평균 | 상세 기록과 별도로 저장하며 재시작 후 복원 |
| Home Assistant Recorder 이력 | Home Assistant의 기록 대상과 보존 정책을 따름 |

일부 상세 데이터가 만료되어도 학습 전체가 초기화된 것은 아닙니다. 장기 문제 분석이 필요하면 만료 전에 JSON을 내려받으세요.

## 학습 기록 마이그레이션

관리자가 사이드바 **바닥난방 → 학습 분석**에서 방을 선택하고 **마이그레이션**을 누르면 복구를 실행합니다. 보존된 시간 초과 회차를 연결한 실내온도 센서의 Recorder 이력으로 재검증합니다. **당시 관측 구간 안에서** 최고점 확정 조건을 통과한 회차는 품질 기준에 따라 가동시간·잔열 예측 모델에 반영합니다.

일출 절약 시간 설정이 활성화되어 있으면 현재 시간 구간을 기준으로 보존된 일출 제외 난방·냉각 회차도 각각 재검증합니다. 실행 후 항목별 복구 건수와 건너뛴 이유를 확인할 수 있습니다. 원래 판정과 복구 근거를 보존하며 재실행해도 이미 복구한 회차는 중복 반영되지 않습니다.

난방기 한 대를 사용하는 방에서는 `HEATER_UNAVAILABLE`로 제외된 난방 회차도 확인합니다. Recorder에 실제 난방 시작·정지 및 실내온도 기록이 남아 있어야 합니다. 난방 정지 후 통신이 끊겼다가 현재 학습 유예 시간 안에 동일한 정지 상태로 복구된 사실이 확인되면 실내온도 이력으로 최고점과 학습 품질을 다시 판단합니다. 유예를 0초로 설정했거나 이력이 부족하면 기존 판정을 유지합니다.

같은 버튼의 **외기 보정 재집계**는 보존된 난방 회차와 외기 센서의 Recorder 이력을 사용합니다. 가동시간 모델에 쓰는 ON~OFF 구간의 시간 가중 평균 외기와 잔열 모델에 쓰는 OFF 시점 외기를 복원합니다. 오래된 회차의 외기 복원이 필요할 때 선택적으로 실행할 수 있습니다. 외기가 누락된 회차도 전체 가동시간 학습에 사용합니다.

## 학습 리셋

센서 위치나 난방 구성의 큰 변경 등으로 기존 학습을 새 환경에 적용하기 어려운 경우 검토하세요. 단순 업데이트나 일시적인 예측 대기만으로 리셋할 필요는 없습니다.

1. 학습 데이터와 진단 JSON을 먼저 내려받습니다.
2. 모드를 OFF로 바꾸고 실제 히터 OFF 및 대기 중인 명령이 없음을 확인합니다.
3. 해당 방의 **학습 리셋**을 실행합니다. 여러 방이면 선택한 기기가 맞는지 확인하세요.
4. 완료 후 원하는 운전 모드로 돌아가 평소대로 학습합니다. 예측 OFF의 유효 3회 조건부터 다시 확인합니다.

리셋은 해당 기기의 학습과 자체 예측 비교를 지웁니다. 기기 설정과 HA Recorder 이력은 유지합니다. 과거 학습이 필요할 가능성이 있으면 실행 전에 복원용 백업도 확보하세요.
