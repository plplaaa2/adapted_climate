# 기본 모델과 커브 모델 작동 설계

이 문서는 2026-10-02 협의한 모델별 작동 규칙과 구현 결과를 정리한다. 아래 계산 기준은 로컬 자동 테스트로 검증했으며 실제 Home Assistant와 난방 장치에서의 검증은 별도다.

## 1. 모델 선택과 공통 운전

- 기본 모델과 커브 모델은 독립적으로 학습하고 저장한다. 셀렉터 선택은 학습 여부를 결정하지 않는다.
- 기본 선택값은 기본 모델이다. AUTO에서는 선택된 모델의 예측을 제어에 사용한다.
- 두 모델은 지속적으로 유지한다. 커브 모델로 기본 모델을 대체하거나 모델 셀렉터를 제거하지 않는다.
- 중앙난방과 개별 보일러 등 설치 환경에 따라 사용자가 모델을 선택한다. 난방 방식만으로 우수한 모델을 단정하거나 자동 지정하지 않는다.
- HEAT는 기본 히스테리시스로 제어하고, OFF는 정상 대기 중 관측한다. 유효한 관측은 모델별 품질 조건에 따라 두 모델의 학습에 사용한다.
- 모델 선택을 바꿔도 저장된 학습값을 삭제하지 않는다. 진행 중 난방을 선택 변경만으로 강제 중단하지 않는다.

## 2. 공통 관측과 안전

실내온도와 확인된 히터 ON/OFF 전환을 관측한다. 스위치 명령 완료를 실제 상태 전환으로 간주하지 않는다. 멀티룸은 전체 스위치의 상태가 일치할 때 전환을 확정한다.

온도 입력 오류, 히터 오류, 과열 등 안전 조건은 예측보다 우선한다. 안전 정지와 사용자 OFF는 최소 ON 시간보다 우선하며, 정상 예측 제어는 최소 ON/OFF 시간을 지킨다.

재시작·재로드 전후의 진행 중 사이클은 이어 붙이지 않는다. 완결되어 저장된 모델은 복원한다. 모델 오류나 학습 부족이 안전 조건을 완화해서는 안 된다.

## 3. 기본 모델

### 학습

실제 센서 보고와 난방 사이클에서 온도 상승·하강 속도, 난방 반응 지연 및 예측에 필요한 시간 특성을 자동 산출하고 누적 학습한다. 사용자가 이 예측용 열특성 값을 직접 입력하지 않는다.

학습값은 실측 이력의 시간 차이를 사용한다. 제어를 위한 현재 온도 조회를 새로운 센서 보고로 만들지 않는다. 불완전하거나 품질 조건을 만족하지 않는 관측은 학습에서 제외한다.

### AUTO ON

일반 시작 기준에 도달하면 난방을 시작한다. 예측 ON이 허용된 정책에서는 현재 냉각 속도와 학습한 난방 반응 지연을 이용해 온도 하강을 예상하고 선제 시작 여부를 판단한다.

### AUTO OFF

현재 온도 상승 속도와 학습한 OFF 후 반응 시간 특성을 결합해 **지금 OFF했을 때의 예상 Peak**를 계산한다. 설정온도와 AUTO 정지 편차로 정해지는 상한에 예상 Peak가 도달하면 정상 OFF를 판단한다.

OFF 시 상승 속도, 가동시간, OFF 후 실제 온도 변화, Peak까지의 시간과 상승량을 함께 관측한다. 이를 통해 상승 속도와 정지 후 반응의 관계를 자동 학습한다. 사용자가 예측 시간을 입력하지 않는다.

ON 중 상승 속도가 OFF 후에도 그대로 유지된다고 가정하지 않는다. 각 유효 표본의 `OFF 이후 Peak 상승량 / OFF 시 상승 속도`로 등가 반응 시간(시간 단위)을 구한다. 현재 가동시간과 상승 속도가 비슷한 표본의 가중 평균 시간을 현재 상승 속도에 곱해 예상 추가 상승량을 계산한다. 이 등가 시간은 실제 Peak까지의 시간과 다른 값이며 둘을 혼동하지 않는다.

기본 모델은 최근 최대 24개 완결 OFF 표본을 별도로 보존한다. 기존 진단 집계값은 유지하며 유효한 0 상승량도 학습한다. 저장 schema 4는 schema 1~3을 보존해 이전한다. 구형 저장소에 유효한 OFF 곡선이 있으면 호환 예측에 활용하지만 없는 응답을 만들어내지는 않는다.

## 4. 커브 모델

### 학습 데이터

확인된 ON부터 OFF 이후 Peak까지의 난방 온도 궤적과 Peak 이후의 냉각 궤적을 학습한다. 5분 경계의 마지막 유효 실내온도로 변화량을 기록하며, 온도 변화가 없는 유효 구간도 0 버킷으로 보존한다. 이 버킷은 기본 모델용 실제 센서 보고를 새로 생성하지 않는다.

커브 종류는 Cold, Warm, Predictive Warm, Cooling이다. 운전 정책 이름과 열상태 분류를 구분한다.

### Cold 분류

Cold 조건은 **AWAY가 연속 3시간 이상 지속된 후 HOME으로 전환한 경우**다. 해당 복귀 후 첫 난방을 Cold로 분류하며, 예측 시작 여부보다 이 분류가 우선한다.

- HOME에서 히터 OFF가 3시간 지속된 것만으로 Cold가 되지 않는다.
- 3시간 미만 AWAY 후 HOME 복귀에는 Cold를 강제하지 않는다.
- AWAY 사이클은 커브 표준 학습에서 제외한다. HOME/AWAY 경계를 넘어 사이클을 이어 붙이지 않는다.
- 그 외 예측 시작은 Predictive Warm, 일반 시작은 Warm으로 분류한다.
- 복귀 첫 사이클이 중단되거나 학습 품질 검사에서 제외되면 Cold 대기를 유지한다. Cold 난방 구간이 실제 학습에 반영됐을 때 해제한다. AWAY 시작 시각과 복귀 대기는 재시작 후 복원한다.

### Peak와 Cooling

OFF 이후 유효한 온도 보고를 순서대로 비교한다. **실제 하강이 처음 확인되면 하강 직전 보고의 온도와 시각을 Peak로 기록한다.**

예: `23.3 → 23.4 → 23.4 → 23.3`이면 두 번째 23.4 보고가 Peak다. 동일 온도 유지나 10분 경과만으로 확정하지 않는다. Cooling은 그 Peak 시점부터 시작한다.

하강 확인 전에 다음 ON·재시작·입력 오류 등이 발생하면 완결된 Peak가 있는 사이클로 취급하지 않는다. Peak 대기는 OFF부터 최대 3시간, Cooling 관측은 Peak부터 최대 3시간으로 분리한다. 다음 ON이나 지속 상승이 먼저 발생하면 Cooling을 종료한다.

### 모델 저장과 예측 입력

Raw 사이클과 학습 표준을 구분한다. 기존 독립 EWMA 버킷 표준을 보존하고, 난방 종류별 최대 24개 완결 OFF 응답을 추가 저장한다. OFF 응답에는 가동시간·OFF 시 상승 속도·OFF 기준 5분 궤적과 정확한 Peak 끝점을 보존한다. Raw 5분 버킷은 7일 후 정리하지만 학습 표준과 OFF 응답은 유지한다. SQLite schema 2는 기존 schema 1 데이터를 보존해 확장한다.

별도 Current/Long-term 계층과 혼합, 지속적인 환경 변화와 이상치 구분은 원래 초안의 후속 설계 항목이다. 이번 구현은 기존 EWMA 표준과 OFF 응답 학습을 사용한다.

### AUTO ON

학습한 난방 버킷에서 최초로 유의미한 상승이 나타나는 시간으로 반응 지연을 구한다. 현재 Peak 이후 경과시간부터 반응 지연까지 Cooling 버킷 변화량을 합산해 반응 시점의 온도를 예상한다. 필요한 모든 버킷에 최소 3개 표본이 있어야 한다. 반응 시점 온도가 설정온도 이하로 예상되면 정책과 최소 OFF 조건에 따라 선제 시작한다. Predictive Warm 반응 지연이 부족하면 Warm으로 대체하며, Cold 대기 중에는 Cold 반응 지연을 사용한다.

### AUTO OFF

현재 난방의 가동시간, 온도 상승 속도와 변화 형태를 과거 사이클의 OFF 시 상태와 비교한다. 유사한 조건에서 관측한 **OFF 이후 온도 궤적**을 이용해 지금 OFF했을 때의 미래 온도와 Peak를 예측하고, 상한에 맞는 OFF 시점을 판단한다.

OFF 시 상태와 이후 응답을 연결하여 학습한다. 난방 커브에는 ON/OFF 전환 위치를 보존하고, OFF 이후 구간은 OFF 기준 경과시간으로 비교할 수 있어야 한다. 과거 사이클이 ON을 유지했던 구간을 지금 OFF한 이후의 응답으로 그대로 합산하지 않는다.

현재 ON 버킷이 해당 표준의 변화 형태와 유사해야 한다. 비교 가능한 OFF 표본들의 시간별 응답을 보간하고 유사도 가중치로 결합해 예상 궤적과 Peak를 구한다. Predictive Warm OFF 표본이 부족하면 Warm으로 대체한다. Cold를 Warm으로 임의 대체하지 않는다. 비교 가능한 사이클이 부족하거나 예측 범위가 학습 범위를 벗어나면 기본 모델로 대체한다.

### OFF 예측의 공통 검증

실제 OFF가 확인될 때 두 모델이 계산 가능한 경우 각각의 예상 Peak를 기록한다. 사이클 완결 후 실제 Peak와 비교해 `예상 − 실제` 온도 오차를 기록한다. Climate의 `off_prediction`은 선택 제어 경로의 현재 예상값을, `last_peak_comparison`은 마지막 완결 비교를 제공한다. 마지막 비교는 재시작 후 복원하지만 진행 중 비교는 이어 붙이지 않는다. 이 비교를 위해 선택되지 않은 모델의 예측이 히터 명령을 내리지는 않는다.

OFF 후 추가 상승은 학습해야 할 물리적 응답이며 두 모델 모두 활용한다. 모델의 차이는 이 응답을 간단한 속도·시간 관계로 표현하는지, 시간별 온도 궤적으로 표현하는지에 있다. 예상 Peak는 결과 보장이 아니며 실제 오차를 통해 현장 적합성을 확인한다.

## 5. 운전 정책과 대체 제어

| 선택 | 예측 ON | 예측 OFF |
| --- | --- | --- |
| Eco | 사용하지 않음 | 선택 모델 사용 |
| Balanced | 보수적으로 사용 | 선택 모델 사용 |
| Comfort | 적극적으로 사용 | 선택 모델 사용 |

정책은 제어 강도를 정하며 학습 모델이나 Cold 분류를 대신하지 않는다. 커브 예측 ON은 Balanced에서 학습 반응 지연의 절반, Comfort에서 전체 시간의 Cooling 궤적을 사용한다.

기본 모델의 예측 데이터가 부족하면 히스테리시스로 운전한다. 커브 모델의 예측 데이터가 부족하거나 저장소를 사용할 수 없으면 기본 모델로 대체하고, 기본 모델도 부족하면 히스테리시스로 운전한다. 대체 사용은 선택된 모델 자체를 변경하거나 학습을 중단하지 않는다.

## 6. 계산 조건과 대체 운전

두 OFF 예측 모두 상승 속도가 0.1°C/h보다 크고 유효한 비교 표본이 최소 3개여야 한다. 가동시간 차이는 현재 가동시간의 35% 또는 10분 중 큰 값 이내, 현재/과거 상승 속도 비율은 0.7~1.3 이내로 제한한다. 적용 범위 밖에서 임의 외삽하지 않는다.

가중치는 `1 / (1 + 가동시간 차이(분)/30 + 속도 비율 차이×3)`다. 신뢰도는 `min(비교 표본 수/8, 1) / (1 + 예상 상승량 표준편차/0.5)`이며 0.25 이상일 때만 사용한다. 이 조건들은 검증을 위한 초기 구현 기준이다. 물리적 반응 시간과 온도 응답은 실제 사이클로 학습한다.

신뢰도는 예측 사용 여부를 결정한다. 예상 상승량에 신뢰도를 곱해 실제 응답을 축소하지 않는다. 학습 부족이면 커브 → 기본 모델 → 히스테리시스 순으로 대체한다. 예측 예외도 안전·최소 시간 조건을 보존하는 기본 결정으로 대체한다.

정지 후 재가동 대기는 실제 OFF 기준 예상 Peak와 학습한 Peak 시간을 우선 사용한다. 새 예측이 없는 경우 기존 잔열·Peak 지연 집계값으로 제한된 대기를 유지한다. 구형 잔열 집계값만으로 새로운 예측 OFF를 결정하지 않는다.
